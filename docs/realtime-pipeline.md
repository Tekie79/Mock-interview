# Real-time processing and latency

| Stage | Queue or owner | Failure behavior |
|---|---|---|
| Native audio | Preallocated callback slots, a bounded native stream and a bounded normalized PCM stream | Overrun terminates that activation and records a minimum dropped-chunk count |
| Recognition | One transport per selected source, opened before capture starts | Authentication and unsupported configurations fail immediately. Stalled sends, unresolved speech and network/rate-limit failures allow at most two retries with fresh epochs and no replay of captured audio |
| Transcript ingestion | Session actor stores up to 2,000 current display rows and consumes provider-ordered events | Late source epochs and repeated final IDs are discarded. Partial updates replace the displayed item |
| Classification | FIFO, 32 waiting final interviewer turns by default, independent of ingestion | Overflow retains the transcript and surfaces a manual action. Queued turns expire; reassignments and source changes cancel affected work |
| Retrieval and answer | One active answer revision; keyword context and optional embeddings run asynchronously | Manual actions supersede older classifier results. New questions supersede older generations. Timeout preserves the partial response and permits retry |
| UI | Latest-value snapshot with throttled level publication | Pinned and unrendered answers have no first-visible measurement until displayed |

Actual candidate speech is a distinct role-labelled, bounded context. It can resolve interviewer follow-ups and never supplies verified experience. Target role/job requirements and locally approved evidence go to providers in separate fields. Suggested answers never enter actual conversation context. Untrusted text remains data. The settings expose turn counts and conservative UTF-8 context budgets for classification and generation.

For graceful replay, the transport stops accepting input, flushes any active commit and waits for expected final events or explicit provider stream completion. The drain has a deadline, including the final send. Unconfirmed audio is surfaced as incomplete, not silently dropped or retried. During live capture, unresolved speech or a stalled write is tracked independently of transport liveness; WebSocket ping/pong checks quiet connections, and ordinary silence is not a recognition failure. Normal EOF lets queued classification and answer work finish. User stop instead cancels uploads, transport consumers, queued classification, and the active answer revision, then acknowledges release. A source failure revokes its epoch. A candidate-only connection is degraded.

Durations use `ContinuousClock`. The native callback records capture time. The manual-commit path associates ordered finals with local speech observations and the commit send. Provider-owned segmentation maps admissible audio ranges against bounded sample-clock anchors for that connection, retaining overlapping or delayed ranges when they can be correlated. Untimed finals may use the oldest local speech observation; invalid, repeated or unmapped ranges do not borrow the newest utterance's timings. Provider-owned commit times remain unavailable unless the provider reports an attributable commit. Diagnostics label the audio timing basis as a mapped estimate, a local speech estimate, or unavailable. The first-visible boundary comes from an acknowledgment of non-whitespace answer text by the SwiftUI view, not a transport fragment or a measured display refresh. These are development observations, not an acceptance latency benchmark.
